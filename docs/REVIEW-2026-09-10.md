# 课程超市：从选课走向共议

本次只改公开站点的使用流程。课程数据、编号、标题、摘要、做法和原有配色均保留，`assets/courses.js` 与修改前逐字节相同。基线版本为 `b22733dc9afc6606fab1ae41ccb720da636ec009`，共 297 门课程。

## 产品判断

现有的“问题、学科、主题”三条入口和书架形态值得保留。下一步的重点，是帮助学校把感兴趣的方向变成可以继续讨论的选择：找到课程 → 放入书篮 → 并排比较 → 写下本校想法 → 带进教师备课会。

## 已实现

- 书篮中勾选 2–4 门进行对照，呈现目录学段、课程意图与内容、主要做法、关联学科和学校想法。各项课程信息直接使用原文，不生成评分或虚构课时。
- 下载整个书篮的 HTML 研讨单，可离线阅读、打印或存为 PDF。适用年级、场地与材料、负责教师、首次试教安排、想观察的学生表现均留作“待共议”。原有流水单功能保留。
- JSON 书篮备份与确认后合并导入。只导出课程编号和使用者备注，保留现有书篮与已有非空备注。对旧编号、冲突、错误格式和超限文件给出提示。
- 学段筛选不再吞掉其他选项，实际目录里的复合学段也能显示；所有入口可清除条件；尚未选择问题或主题时可以检索全库；多个关键词按空格组合检索。
- 本机存储不可用时继续允许选课、写备注与导出，明确提示未写入本机。继续兼容原有书篮存储键。
- 书篮支持键盘焦点约束和返回；关闭时禁止隐藏控件获得焦点；比较页按区域横向滚动。
- 浏览顺序说明收束为公开条目信息完整度与学科多样性，避免将这些因素表述成课程质量或实施难度的判断。
- Service Worker 只清理当前站点作用域内的新命名缓存，避免清空同域其他应用的缓存；补充完整静态资源预缓存、请求失败回退与缓存写满保护；移除写备注期间可能发生的强制整页刷新。

## 文件结构

`assets/catalog-core.js` 为无界面依赖的筛选、存储、备份和导出逻辑。`assets/app.js` 保留原有页面组织，并提供小范围的书篮接口。`assets/review.js`、`assets/review.css` 承载课程共议界面。无需构建工具、后端、账号或新增第三方前端依赖。

## 已完成的检查

1. `node --test tests/*.test.cjs`：38 项通过，覆盖真实目录结构、过滤逻辑、异常存储、备份校验与合并、文本转义、HTML 导出及缓存逻辑。
2. `python tests/browser-smoke.py --in-memory`：16 项通过。使用本地生产源码在 Chromium 中检查交互和 1440、768、375 像素宽度。覆盖勾选上限、对照与备注回写、实际文件下载、导入确认、错误文件不改书篮、原流水单和存储不可用提示。
3. 课程数据文件与基线逐字节相同，正文没有重新生成。

浏览器检查的 `--in-memory` 模式使用存储替身，不经过 HTTP，也不注册 Service Worker。当前执行环境禁止浏览器连接本地 HTTP 服务，因此真实浏览器刷新持久化、Service Worker 离线重载、真实 iPhone/Safari 和部署域名的缓存切换尚未完成验收。Node 的缓存模拟测试不能替代这些检查。

## 合并前的验收

在允许本地 HTTP 的环境安装 Python Playwright 及 Chromium 后，运行 `python tests/browser-smoke.py`；浏览器路径可通过 `CHROMIUM_PATH` 设置。完成普通刷新、断网刷新、域名子路径、历史书篮恢复和手机操作的验证。真实 Safari 另行人工验收。

测试只使用公开目录与临时备注。演示站没有多人实时协作、云同步、自动排课或学生选课报名能力；“共议”指围绕同一个本机书篮开展讨论。

发布流程应继续走独立分支和 Pull Request。不要将评审分支直接作为生产部署源。

## 后续生成目录时

生成新的页面时需保留 `catalog-core.js → app.js → review.js` 加载顺序及 `review.css`，并同步 `sw.js` 的资源版本与预缓存列表。测试会检查依赖顺序、缓存资源与页面引用是否一致。当前仓库未包含页面生成器，因此本轮没有修改生成器。

## 后续值得做的方向

优先考虑“学校课程组合”：使用者将选中的课程整理为全员经历、年级重点或自主选修，并写明与本校育人目标的联系。自动化结构分析应建立在可公开、经确认的年级、课时、资源与实施条件字段上；本轮不从课程简介猜测这些数据，也不生成看似完整的学校方案。
